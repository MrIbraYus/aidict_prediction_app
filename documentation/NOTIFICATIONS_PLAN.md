# AIDICT — Notifications & Sound System

**Date:** 2026-11-26 · **Status:** web behaviour implemented in the prototype · Android planned for Stage 7

## 1. Categories and defaults
| Category | Default in-app | Default sound | Default desktop | Sound file | Priority | Cooldown |
|---|---|---|---|---|---|---|
| New prediction available | on | **off** (frequent; one alert per publishing run) | off | `new-prediction.wav` | 1 | 60 s |
| Match starting soon | on | on | on | `kickoff-soon.wav` | 4 | 10 s |
| Match going live | on | **off** (avoids two alerts per kick-off) | off | `match-live.wav` | 3 | 10 s |
| Goal scored | on | on | on | `goal.wav` | 6 | 4 s |
| Match finished | on | on | off | `match-finished.wav` | 4 | 10 s |
| Prediction result settled | on | on | off | `prediction-settled.wav` | 5 | 10 s |
| Important system notices | on | on | on | `system-alert.wav` | 2 | 30 s |

Global defaults: sounds **on**, volume **60%**, match alerts for **saved matches only**, kick-off reminder **30 min** before, quiet hours **23:00–07:00 available but off**, desktop alerts **off until you allow them**.

## 2. Sounds
- Seven **original** sounds generated by `prototype/scripts/generate-sounds.mjs` (additive synthesis). No third-party audio, so there is no licence risk; they are CC0 within the project.
- Short (0.55–1.05 s), mono, 44.1 kHz, every file normalised to −3 dBFS peak so no category is louder than another.
- Character: soft marimba (prediction), rising glass (starting soon), double tap (live), quick bright arpeggio (goal), resolving descent (finished), warm bell (settled), two low even tones (system).
- Manifest: `prototype/public/sounds/manifest.json`. Production converts the files to `.ogg` / `.m4a` for size. Android uses `.wav`/`.ogg` in `res/raw`.

## 3. Rules that keep it calm (all enforced in `lib/notify.ts`)
1. **De-duplication:** every event has a stable `dedupeKey` (e.g. `goal:{fixture}:{score}`, `ft:{fixture}`). A key alerts **once**. Production stores it in `notification_events` with a unique index.
2. **Scope:** match alerts only for saved matches by default (or saved plus favourite teams, or all).
3. **Merge:** full time and the prediction settlement for the same match within 2 minutes become **one** notification and **one** sound.
4. **Burst coalescing:** events within 600 ms produce **one** sound (the highest priority) and at most 3 pop-ups. The rest are summarised.
5. **Throttling:** at most one sound every 1.5 s, 6 per minute, and per-category cooldowns.
6. **Quiet hours:** sounds are silenced and the inbox is still updated.
7. **No double alerts:** when the tab is hidden and desktop alerts are allowed, the OS notification plays the OS sound and AIDICT stays silent.

The prototype's **Simulate notification events** card (Notifications page) runs events through these rules and shows a delivery log: *Sound played · Duplicate suppressed · Merged with full time · Merged into burst · Category silent · Not in alert scope · Throttled · Quiet hours*. These outcomes were verified in Edge with `scripts/check-notifications.mjs`.

## 4. Browser constraints handled
- **Autoplay:** browsers block audio until the user interacts. The engine creates and resumes its `AudioContext` on the first click, key press or touch. Before that, events still appear in-app and the log shows *Blocked until first click*. Settings explains this in one line.
- **Permission:** `Notification.requestPermission()` is called **only** from the "Allow desktop alerts" button, never on page load. Status is shown as *Not requested · Allowed · Blocked in browser (with how to re-enable) · Not supported*.
- **Volume:** Web Audio gain node, 0–100%, applied to every AIDICT sound. The OS volume still caps it. iOS Safari's mute switch silences web audio, and the docs say so.
- **Preview:** each category has a ▶ Play button. Previews skip throttling but follow the volume slider.
- **Mobile web inputs** use 16 px text, so iOS Safari does not auto-zoom when the search field is focused.

## 5. Where events come from (honest latency)
| Event | Generated by | Realistic latency on the free tier |
|---|---|---|
| New prediction | `predict_upcoming` job (GitHub Actions, 4× daily) | Immediate after the job |
| Starting soon | Client-side scheduler while the app is open. Hourly job sends Web Push for matches starting in the next 75 min | Exact while open. Within the hour when closed (precise on Android via local scheduling) |
| Going live / Goal | Live refresh while the Live page or a saved match is open. OpenLigaDB for German leagues | OpenLigaDB: near real time. football-data.org free tier: **delayed**. API-Football: 100 calls/day budget |
| Finished / Settled | `sync_current` (hourly) + `settle_results` | Up to ~1 hour |
| System | Sync jobs, model gates, conflict detector | Next job run |

**Real-time goal alerts for all leagues are not possible on free data.** The upgrade path is football-data.org "Free w/ Livescores" (€12/mo). Every alert shows its source.

## 6. Production data model (additions)
| Table | Purpose |
|---|---|
| `notification_events` | `id`, `category`, `fixture_id?`, `dedupe_key` **unique**, `payload jsonb`, `source`, `created_at` |
| `notification_deliveries` | `event_id`, `user_id`, `channel` (`in_app` · `web_push` · `android`), `status`, `delivered_at`. Unique `(event_id, user_id, channel)` prevents double delivery |
| `push_subscriptions` | `user_id`, `platform` (`web` · `android`), `endpoint` / `expo_token`, `keys jsonb`, `created_at`, `last_seen_at` |
| `user_preferences.notification_prefs` | The `NotifPrefs` JSON from the prototype (categories, volume, scope, quiet hours, lead time) |

Web Push: a service worker plus VAPID keys. Pushes are sent by the GitHub Actions jobs using `pywebpush`. No paid service is needed.

## 7. Android (Stage 7 plan)
Built with **expo-notifications** (local and push via the Expo Push Service / FCM). It does **not** start until you approve the tested web app.

| Channel ID | Name shown in Android settings | Importance | Sound |
|---|---|---|---|
| `aidict.predictions.v1` | New predictions | LOW (no sound, silent badge) | `new_prediction.wav` (opt-in) |
| `aidict.kickoff.v1` | Match starting soon | HIGH | `kickoff_soon.wav` |
| `aidict.live.v1` | Match going live | DEFAULT | `match_live.wav` |
| `aidict.goals.v1` | Goals | HIGH | `goal.wav` |
| `aidict.results.v1` | Match finished | DEFAULT | `match_finished.wav` |
| `aidict.settlement.v1` | Prediction results | DEFAULT | `prediction_settled.wav` |
| `aidict.system.v1` | Important notices | DEFAULT | `system_alert.wav` |

- **Channels are immutable after creation** (Android 8+): sound and importance cannot be changed by the app later. The `.v1` suffix lets a new version be created (`.v2`) and the old one deleted if a sound changes.
- Custom sounds are bundled through the `expo-notifications` config plugin (`sounds: [...]` in `app.json`) into `res/raw`. File names must be lowercase with underscores.
- Users control each channel in Android system settings. The in-app settings screen mirrors those controls and deep-links to them.
- **Kick-off reminders** are scheduled locally on the device (`scheduleNotificationAsync`) when a match is saved. They are exact and need no server.
- **De-duplication:** the same `dedupe_key` is used as the notification `identifier`, so a repeat replaces instead of stacking. Related alerts use `threadIdentifier` and group summaries per match.
- **Permission:** `POST_NOTIFICATIONS` (Android 13+) is requested in context, after the user saves a first match or enables alerts, never on first launch.
- Respects Do Not Disturb and channel importance. No full-screen intents, no exact alarms beyond kick-off reminders.
